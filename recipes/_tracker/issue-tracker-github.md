# Issue tracker: GitHub

Work items for this repository live as GitHub Issues; pull requests are the review surface. Use
the `gh` CLI for every operation; it infers the repository from the remote when run in a clone.

## Operations

- **List**: `gh issue list --state open --limit 200 --json number,title,labels,updatedAt,author` (add `--label <state>` to filter by state)
- **Read**: `gh issue view <n> --comments --json number,title,body,labels,author,createdAt,comments`
- **Comment**: `gh issue comment <n> --body "..."` (a heredoc for multi-line bodies)
- **Change state**: `gh issue edit <n> --add-label "<new state>" --remove-label "<old state>"` — exactly one state label at a time
- **Claim**: `gh issue edit <n> --add-label agent-working --remove-label ready-for-agent --add-assignee @me`
- **Close**: `gh issue close <n> --comment "..."`
- **Pull requests**: `gh pr create`, `gh pr list --state open --json number,url,headRefName,reviewDecision,comments,updatedAt`, `gh pr view <n> --comments`, `gh pr diff <n>`

## State vocabulary

One category label (`bug` | `enhancement`) and exactly one state label per open issue. The state
labels are `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `agent-working`,
`in-review`, `agent-blocked`, `wontfix`. The recipe's setup script creates them; a playbook that
moves an issue names the label it moves to.

## Blocking

A `Blocked by: #<n>, #<m>` line near the top of an issue body (or the tracker's native
dependency) gates it: the item is unblocked when every listed issue is closed.

## Who counts as the agent

Comments and assignments made by loops are made as the account `gh` is signed in as. Every comment
a loop posts starts with a line saying it was generated by AI.
